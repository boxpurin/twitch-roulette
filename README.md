# Twitch Roulette

Twitch OAuth でログインし、指定したチャンネルポイント報酬を交換した視聴者をルーレットに登録する React / TypeScript / Vite のブラウザアプリです。バックエンドなしで動作します。手動での項目追加も可能です。

## ローカルでログインする

1. [Twitch Developer Console](https://dev.twitch.tv/console/apps) でアプリを登録します。登録にはメール認証と二要素認証が必要です。
2. **OAuth Redirect URLs** に `http://localhost:5173/` を追加します。末尾の `/` を含め、後述の設定と一致させてください。
3. クライアント種別の選択がある場合は **Confidential** を選びます。Twitch の Public クライアントは Device Code Flow 専用のため、このアプリの Implicit Flow では使用しません。Client Secret は作成・設定・配布する必要がありません。
4. 管理画面の **Client ID** を控えます。Client ID は公開識別子です。Client Secret やアクセストークンとは異なります。
5. 設定ファイルを用意します。

   ```bash
   cp .env.example .env.local
   ```

   `.env.local` を編集します。

   ```dotenv
   VITE_TWITCH_CLIENT_ID=ここにClient_IDを設定
   VITE_TWITCH_REDIRECT_URI=http://localhost:5173/
   ```

   `VITE_` 設定はブラウザの配信コードに組み込まれます。ここに秘密情報は入れないでください。既存 `.env` の `TWITCH_API_TOKEN` はこのアプリでは使用しません。

6. 起動します。環境変数を変更した場合はサーバーを再起動してください。

   ```bash
   pnpm install
   pnpm dev
   ```

7. `http://localhost:5173/` を開き、**Twitch でログイン** を押します。Twitch 上で配信者アカウントとして許可すると、元の画面にログイン名とユーザー ID が表示されます。

開発ポートは 5173 に固定しています。使用中の場合は起動が失敗します。ポートを変えるときは、Twitch の登録 URL・環境変数・起動ポートをすべて合わせてください。`localhost` と `127.0.0.1` は別のホストです。

## ルーレットを回す

ログイン後、項目名を入力して「項目を追加」を押し、円盤直下の「ルーレットを回す」で抽選します。約4秒で減速して停止し、上部の矢印が指す当選項目を円盤下に表示します。

- 抽選対象が0件の場合（全項目を除外した場合も含む）と演出中は回すボタンが無効になります。
- 演出中は項目の追加・編集・削除・除外の切り替えも無効になります。停止後は再編集・再抽選できます。
- 当選確率は「本人の倍率 ÷ 抽選対象の倍率合計」です。倍率 1 と 3 の場合は 25% と 75%、全員 1 倍なら均等です。円盤の面積も同じ比率です。
- 項目の「編集」で名前と倍率を変更できます。倍率は 1 以上の安全な整数です。当選した項目を自動削除しません。
- 各項目の「抽選から除外」にチェックすると、名前・倍率・交換回数を残したまま抽選と円盤から除外できます。チェックを外すと復帰します。除外中に同じ視聴者が再交換しても倍率と交換回数は増えますが、除外は解除されません。
- 項目・交換回数・倍率・除外状態は localStorage に保存します。当選結果はメモリ内だけで保持します。
- Canvas 2D で円盤を描画し、回転中だけ描画フレームを予約します。停止・画面破棄時にはループを終了します。

## チャンネルポイント連携

1. ログインすると配信者自身のカスタム報酬一覧を自動取得します。「対象報酬」のドロップダウンから報酬名を選び、「報酬を選択」を押します。必要ポイント数も表示されます。
2. 「受付を開始」を押し、「報酬交換を受信しています。」と表示されてから交換を受け付けます。報酬を変更する前に受付を停止してください。
3. 初回の交換で視聴者名を倍率 1 の項目として登録します。同じ Twitch ユーザー ID の再交換は、一項目の現在倍率へ 1 を加算します。2 回なら 2 倍、3 回なら 3 倍です。手動で 5 倍に変更した後の再交換は 6 倍です。
4. 一覧で交換回数・倍率・当選確率を確認できます。同名でもユーザー ID が異なれば別項目になります。手動項目は視聴者の項目と独立しています。
5. 回転中に届いた交換も保存します。抽選対象は回転開始時に固定し、到着分は回転終了後の一覧・次回抽選に反映します。

一覧は Twitch の [Get Custom Reward API](https://dev.twitch.tv/docs/api/reference/#get-custom-reward) から、既存の読み取り権限で取得します。Twitch 管理画面で作成した報酬も含みます。報酬 ID を調べる必要はありません。取得失敗・タイムアウトでは「報酬一覧を再取得」を押してください。報酬がない場合は Twitch 側でカスタム報酬を作成してから再取得します。

保存済みの報酬は一覧取得後に名前で表示されます。保存済みの報酬が削除されていても履歴は消さず、一覧に見つからない旨を表示します。その報酬での受付開始は無効になるため、別の報酬を選んでください。取得中や、受付中・回転中は報酬を切り替えられません。

EventSub WebSocket の welcome 後に、既存の `channel:read:redemptions` 権限で報酬交換イベントを購読します。同じ交換 ID・通知メッセージ ID は二重加算しません。keepalive のタイムアウト・通常切断後は再接続と再購読を行い、Twitch の再接続指示では購読を引き継ぎます。受付停止・ログアウトでは WebSocket と監視・再試行タイマーを終了します。WebSocket の切断に伴い Twitch 側の購読も無効化されます。

受付停止中・切断中の交換や、利用開始前の過去の交換を遡って取得しません。接続エラー・購読失敗・権限取消は画面に表示します。認証期限切れでは再ログインしてください。報酬交換のキャンセル・返金による倍率の減算は行いません。

## 履歴の保存とリセット

- 項目・表示名・倍率・交換回数・重複排除に必要な ID を、配信者 ID と報酬 ID ごとに localStorage へ保存します。選択した報酬 ID も次回ログイン時に復元します。報酬未選択の手動項目には独立した保存先があります。
- 再読み込み・ログアウト後も履歴は残り、同じアカウントで再ログインすると復元します。アプリが実際に受信した交換のみ累積します。
- 「履歴をリセット」→「削除してリセット」で、現在の保存先の全項目（手動項目を含む）・交換回数・倍率・当選結果を消去し、受付を停止します。確認の「キャンセル」では削除しません。回転中はリセットできません。
- リセット時刻以前の交換の再送は無視します。受付を再開した後の新しい交換から倍率 1 で再登録します。別報酬・別アカウントの履歴は消しません。
- 保存制限・容量不足・破損データは画面に表示します。保存できない場合もメモリ内で抽選できますが、変更が残るとは限りません。破損・未対応データは、明示的にリセットするまで上書きしません。
- 履歴はこのブラウザの同一オリジン内だけで保存され、サイトデータの削除で失われます。複数タブで同時に操作すると後の保存で上書きされるため、一画面で利用してください。別ブラウザ・端末・OBS ソースとの同期はありません。
- OAuth トークンは履歴に含めず、引き続きメモリだけで保持します。

## 認証方式と制約

Twitch 公式がブラウザアプリ向けに説明している **Implicit Flow** を使用します。AGENTS.md の Authorization Code Flow + PKCE 方針からの変更は、この認証実装についてユーザー承認済みです。現行公式資料の Authorization Code Flow は Client Secret が必須で、PKCE の対応は確認できていません。

- 要求権限は、報酬交換読み取りに必要な `channel:read:redemptions` のみです。
- ログインごとに暗号学的乱数の `state` を作成し、sessionStorage に10分間だけ有効な要求情報として保存します。戻り値との一致を検査し、一度使った要求は削除します。
- Twitch からフラグメントに返されたトークンは、起動時に URL と履歴から除去します。`/oauth2/validate` で Client ID・ユーザー ID・権限・有効期限を確認した後に認証済みとします。
- アクセストークンはメモリだけに保持し、localStorage・sessionStorage・設定ファイル・ログには保存しません。ブラウザに読み込んだ情報を、そのブラウザ自身から秘匿することはできません。
- 一時間ごとに再検証し、期限切れ・検証失敗・ログアウト・ページ離脱時にセッションを終了します。タブを再表示した際にも期限と再検証の必要性を確認します。通信のタイムアウトは15秒です。
- 再読み込みすると再ログインが必要です。自動更新・リフレッシュトークン保存は行いません。
- ログアウトはこの画面のセッション終了です。Twitch 上のアプリ許可も取り消す場合は、[Twitch の接続設定](https://www.twitch.tv/settings/connections) で解除してください。
- 他ブラウザ、複数端末、OBS ブラウザソースとの同期はありません。OBS では通常ブラウザのこの画面をキャプチャしてください。

## 静的ホスティング

本番の HTTPS URL を Twitch の OAuth Redirect URLs と `VITE_TWITCH_REDIRECT_URI` に設定し、`pnpm build` の出力 `dist/` を配信します。設定はビルド時に反映されます。戻り先 URL でこのアプリの HTML が返るようホスティングを設定してください。HTTP はループバックでの開発時のみ許可します。

## 検証

```bash
pnpm typecheck
pnpm lint
pnpm test --run
pnpm build
```

`pnpm test --run` は `pnpm test` を一回実行で終了する指定です。単体テストでは Twitch 通信をモックします。state・トークンの検証、期限切れ・再検証・中断・遅延応答、認証画面に加え、項目管理、固定乱数での抽選、矢印と停止角度の一致、二重開始防止、停止・破棄時のフレーム終了を検証します。報酬交換のフィルタリング・重複排除、再接続、手動倍率、倍率付き抽選と停止位置、保存復元・保存失敗・リセット、回転中の到着分の保留も検証します。

実接続の確認では、ご自身の Client ID を設定し、ログイン → 許可 → ユーザー表示 → ログアウトを確認してください。認可をキャンセルした場合にエラーから再試行できることも確認できます。報酬の受付開始 → 別アカウントで同じ報酬を 2 回交換 → 一項目が 2 倍になること → 手動倍率編集 → 抽選 → 再読み込み・再ログイン後の復元 → 履歴リセットも確認してください。モックテストの成功は実アカウントでの認可・報酬交換受信や、OBS 環境での負荷測定の代わりにはなりません。
